# Extending fca-reconcile

For the PM and engineering pod taking this tool over: where it is built to grow, and which built-in assumptions will need to change first. Rules (R1–R31) are described in [RULES.md](RULES.md), open product questions in [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md), and the review-list breakdown in [REDUCING_REVIEW.md](REDUCING_REVIEW.md).

## Part 1: Built to be extended

| Extension point | Where | How to extend | Test to add |
|---|---|---|---|
| **Lookups** (buildings, asset-type spellings, manufacturers, partner condition words, serial placeholders, note keywords, columns) | `mappings.py` (data only). Loaded into lookups by `build_lookup` in `reconcile.py`. Accepted asset types are read from `Asset_Types.xlsx` each run (`read_accepted_asset_types`, `build_asset_type_lookup`). | Add a spelling to the right list. To use FMX's source of truth instead, replace the module-level tables with a loader that returns the same shape (`{correct value: [spellings]}`). Nothing downstream changes. `check_asset_type_mappings` and `build_lookup` already reject unknown targets and conflicting spellings. | A parametrized case in `test_R4_*`, `test_R5_*` or `test_R6_*`. For a loader: a test with a stub source that returns a known table. |
| **One function per rule, with rule IDs** | `reconcile.py`: e.g. `parse_install_year` (R9), `check_serial_rounded` (R13), `check_notes` (R15). Rule text in `docs/RULES.md`. | A row-level check is a function returning a `Problem(field, category, reason, value)` or `None`, appended in `clean_record`. Cross-row checks go after cleaning (see `flag_serials_in_several_buildings`) or after flagging (see `flag_identical_ready_rows`). Add the rule to RULES.md with the next ID (R32) and comment the code with that ID. | `test_R32_<behavior>` with a tiny hand-made row (helpers `tech_record` and `partner_record` in `tests/test_rules.py`), and the rule name in `RULE_NAMES` in `tests/conftest.py`. |
| **Review reasons as plain sentences** | Each `Problem.reason`; `category` is the short label counted in the run summary. Reasons are joined with " \| " in `flag_row`. | Write the reason for a data specialist: what is wrong, the value, and what to check. Reuse an existing category if one fits, so the summary counts stay stable. Add a row to the reasons table in README section 4. | An exact-text assertion on the reason (see `test_R19_gap_of_two_uses_lower_rating_and_flags`). |
| **Unrecognized-values report as a feedback loop** | `unrecognized_values` plus `unrecognized_section` produce "Values the tool didn't recognize" in `run_summary.md`. Only problems that set `Problem.value` appear in it. | Set `value` on any new "unrecognized" problem so it shows up in the report. Next step: write the same list as a CSV that a specialist can mark up, and turn the confirmed entries into lookup entries (OPEN_QUESTIONS #3). | `test_R22_summary_lists_every_unrecognized_value_by_field`. |
| **full_detail.csv keeps every captured field** | `make_record` (`original`, with `unique_headings`), `write_full_detail`, `check_full_detail_matches_import`. | New source columns flow through automatically with a `technician_`/`partner_` prefix. A new source needs its own prefix in `write_full_detail` and an entry in `result["original_columns"]`. | `test_R30_*`; add a case for the new source's columns. |
| **Pipeline stages: load → clean → match → flag → write** | Load: `check_input_files`, `load_technician`, `load_partner`. Clean: `clean_record`. Match: `find_duplicates`, `process_group`, `merge_duplicate`. Flag: `flag_row`, then the cross-row checks. Write: `write_outputs`. `reconcile()` runs everything except writing; `main()` adds the file checks and safe writing. | Each stage takes and returns plain dicts and lists, so a stage can be replaced without touching the others (for example, swap `find_duplicates` for a tag-aware version). Row errors are contained per row (`fallback_row`), and `check_row_accounting` (R21) guards every stage. | Unit tests on the replaced stage, plus `test_R21_*` and the `test_UNSEEN_*` full runs, which must still pass. |
| **Test suite as a safety net** | `tests/test_rules.py` (one or more per rule), `tests/test_failures.py` (file problems, broken rows, safe writing), `tests/fixtures/` (made-up unseen files). 203 tests run in about 2 seconds; `conftest.py` prints a pass count per rule. | Run `python -m pytest` before every change. When a rule changes on purpose, update its test in the same commit. Add a fixture file for each new source format. | n/a |

## Part 2: Assumptions that will limit it

Ranked by how soon each will cause problems.

| # | Assumption | Where it lives | What breaks | Suggested change |
|---|---|---|---|---|
| 1 | **The three Lakeview buildings, and the keyword rule** | `mappings.BUILDINGS`, `mappings.BUILDING_KEYWORDS`, `match_building_keywords` | The next district: every row is either flagged "not recognized" or keyword-matched to a Lakeview building (any "High" becomes Lakeview High School, flagged "confirm"). | Load buildings per district from FMX's site/building list. Restrict keyword fallback to that district's buildings, or drop it. |
| 2 | **One district per run** | No district field anywhere; `find_duplicates` keys on (building, serial). | Two districts in one run could merge units across districts when building names collide ("High School"). The coverage table and summary assume one site. | Add a district/site ID to every record and to the match key. Run one district per output folder until then. |
| 3 | **Fixed column headings** | `mappings.TECHNICIAN_COLUMNS`, `PARTNER_COLUMNS`; checked in `check_columns` | Any other partner firm or capture app: the run stops at the file check (cleanly, with the columns found listed). | The column-map file (OPEN_QUESTIONS #8): written when headings aren't recognized, filled in once per source format, reused automatically. |
| 4 | **Two condition scales (technician 1–10, partner Good/Fair/Poor/Critical)** | `convert_condition_10pt`, `convert_condition_text`, `mappings.PARTNER_CONDITION`; chosen by `source` in `clean_record` | A source using 1–5, A–F, or a different word set: its ratings are flagged, or worse, misread if it uses 1–10-looking numbers on another scale. | Declare the scale per source in the column-map file. Never infer it from the values. |
| 5 | **Exactly two sources, one technician and one partner** | `reconcile(technician_path, partner_path, ...)`; the `"technician"`/`"partner"`/`"both"` strings in `merge_duplicate`, `source_label`, `single_row`, `coverage_lines`, `write_full_detail`; `main()` takes two files | A second partner (an elevator or fire alarm contractor), or a past assessment as a third source, has no place to go. Source priority in R17–R19 is technician-versus-partner only. | Make sources a list of `{name, file, column map, condition scale, trust order}`. Have `merge_duplicate` use the trust order instead of hard-coded preference. `source` becomes a list of names. |
| 6 | **Single-sheet files** | `read_excel_rows`: the technician file uses the first sheet, the partner file the `Equipment` sheet. Other sheets are listed by `unread_sheets`. | A technician workbook with one tab per building: only the first tab is read. The others are **now warned about** ("Sheet 'Middle School' in the technician file was not read." on screen and in the run summary), but their rows are still not processed. | Read every sheet that has the expected headings, or name the sheets in the column-map file. Until then, the warning is the safeguard. |
| 7 | **Matching only on serial number** | `serial_key`, `find_duplicates` (R16) | Units without readable serials never merge (FMX data: RTU-4, B-3, AHU-2, panel LP-2A). With more sources, more duplicates get through, each flagged on one side only. | Tag matching within a building (REDUCING_REVIEW bucket 3), as a suggestion first ("possibly the same unit as…"), and automatic only after it has been validated. |
| 8 | **Partner description format** ("Type TAG, details") | `partner_asset_type_text`, `check_multi_unit` | Another partner's description style, or "qty 4" without brackets: the asset type falls through to "not in accepted list". | Map type and tag to separate columns in the column-map file. Keep description parsing only as a fallback. |
| 9 | **Year rules: the two-digit cutoff and misread thresholds** | `parse_install_year` (cutoff = current year's last two digits), `DATE_YEAR_MISREAD_BEFORE = 1950`, `TWO_DIGIT_MISREAD_BEFORE = 1970`; the R18 tolerance of 2 years in `merge_install_year` | Historic buildings with genuinely pre-1970 equipment get flagged. Over decades, two-digit years drift. The tolerance assumes the partner year is year of manufacture. | Move the thresholds into configuration per source and asset type. Keep the current year injectable (`reconcile(current_year=...)`, as the tests already do). |
| 10 | **English-only note keywords and messages** | `mappings.NOTE_KEYWORDS`, `REPEAT_NOTE_KEYWORDS`; every reason and stop message | Notes in Spanish ("fuera de servicio") aren't flagged; non-English-speaking reviewers get English reasons. | Keyword lists per language in the lookups. Message strings keyed by `category` so they can be translated. |
| 11 | **Row IDs are spreadsheet row numbers** | `make_record` (`technician:N`, `partner:N`) | A CSV with line breaks inside cells shifts the numbering. Re-sorting a source file changes every ID. | Keep row numbers for people. Add a stable hash of the original row for machines. |
| 12 | **Whole run in memory; one output set per folder** | `reconcile()` returns everything; `write_outputs` replaces the folder's four files | Fine at this size (201 rows in under a second). Not suited to a portfolio-wide run, or to comparing this year's assessment with last year's. | Stream per building or district, and write each run to a dated folder if run history is needed. |
